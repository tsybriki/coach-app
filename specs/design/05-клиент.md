# 05 · Клиент (PWA)

Уровень: физический. Отвечает на вопрос «что видит пользователь и как работает без сети».

## Форма

PWA: одна страница, статические файлы, service worker, манифест. Без сборщика в MVP —
чтобы приложение собиралось и дебажилось без node-тулчейна.

```
client/
  index.html
  app.js            состояние экрана, роутинг, работа с outbox
  api.js            fetch-обёртка: ETag, ретраи
  store.js          IndexedDB: снапшот, outbox, метаданные
  sw.js             service worker: кэш оболочки, сетевая стратегия
  chart.js          графики разбора тренировки
  link.js           выбор и сортировка кандидатов на связывание
  structure.js      сборка шагов в сеты — чистые функции
  style.css
  manifest.json
```

`manifest.json` объявляет пустой список иконок — каталог `client/icons/` в проекте
не создан. Установка на экран работает, но без своей иконки.

## Двухэкранная навигация недели

Механизм — **из эталонного `plan-wN.html`** (`~/coach/lib/render_html.py`):

- **Экран 1 (список).** Плашки тренировок: иконка вида спорта, день и время,
  длительность, название, фокус. Плашка — кнопка.
- **Экран 2 (детали).** По нажатию на плашку: цель сессии, «зачем» (rationale),
  что взять с собой (инвентарь), структура тренировки. Кнопка «←» в шапке
  возвращает к списку.
- **История.** `history.pushState` + хэш в адресе: кнопка «назад» телефона
  возвращает к списку, ссылка на детали открывается напрямую. Хэш — латиницей
  (`#w3-пн-качественная-vo2max`): кириллица в URL ломает кодировку.
- **Сеты.** Шаги с одинаковой группой собираются в один блок: шаги с повтором
  (`round`) — это интервальный сет, шаги с упражнениями (`label` + `reps`) —
  список упражнений.

## Связывание факта с тренировкой

Связывание живёт **внутри деталей тренировки**, не на экране недели.

- Блок «Факт» в деталях: если факт привязан — «Выполнено» с цифрами и кнопкой
  «Отвязать»; если нет — список кандидатов.
- **Кандидаты** — свободные факты совместимого вида спорта: беговой тренировке
  беговые, велотренировке веловые. ОФП, силовая и HIIT — одна группа.
- Порядок кандидатов: вид спорта (бег первым), внутри — дата от самой старой.
- Занятый факт из списка исчезает: связь хранится с обеих сторон — у тренировки
  `actual_id`, у факта `linked_workout_id`. Без обратной ссылки факт оставался бы
  «свободным» и предлагался бы снова.
- Связанная тренировка в списке недели: галочка и строка с цифрами факта.
- Кнопка «Загрузить факт из Garmin» — рядом со списком кандидатов: без
  загруженного факта связывать нечего. Команда `pull_fact`; в офлайне она уходит
  в очередь и выполняется при появлении сети.

## Нижняя навигация

Разделы — внизу, иконка и подпись, активный подсвечен. Шапка сверху: заголовок
экрана, счётчик версии, обновить.

Разделов **5**, не шесть: «Связывание» живёт внутри недели — факт это часть
работы с неделю, а не отдельный раздел.

| Раздел | Что внутри |
|---|---|
| Неделя | план недели, детали тренировки, связывание факта |
| Факт | план против факта |
| Сезон | макро-план сезона: фазы, недели, факт закрытых |
| Закрыть | ритуал закрытия недели |
| Атлет | профиль |

Кнопки недели строятся по статусу: `proposed` → «Предложить заново» + «Активировать
неделю», `active` → «Закрыть неделю», `closed` → итог и никаких действий. Без кнопки
активации неделя оставалась бы `proposed`, а закрытие отклонялось бы.

## Экраны

1. **Неделя** — план недели: дни, тренировки, шаги, факт рядом с планом.
   У каждой тренировки в шапке — день недели, дата и время: без них её
   нельзя положить в календарь. День и дата считает сервер (по окну), клиент
   только показывает.
2. **Детали тренировки** — второй уровень: шаги, фокус, зоны, что ожидалось и что
   сделано; блок «Факт» со связыванием.
3. **Разбор тренировки** — третий уровень: агрегаты, отрезки, зоны пульса, графики.
   Свой хост в `index.html`, свой заголовок, своя кнопка «назад».
4. **Сезон** — макро-план сезона целиком: цель и гонка, фазы со своими
   неделями, у каждой недели фокус и объём. Закрытая неделя помечена фактом,
   тап открывает её; у текущей и будущих недель факта нет — план ещё не
   исполнен.
5. **План против факта** — неделя: плановые и фактические цифры рядом, вердикты по сессиям.
6. **Закрытие недели** — три шага ритуала: вытянуть факт → сопоставить → посчитать.
7. **Атлет** — профиль: VDOT, зоны, вес, травмы, окна тренировок.

Окна тренировок — часть карточки атлета, а не недели: окно принадлежит среде
и повторяется каждую неделю. Показываются день, время и вместимость, итого
сколько часов в неделю доступно.

**Не реализовано в клиенте:** «Цель и достижимость», «Контрольная точка»,
«Среда» — экранов нет. Команды `set_goal`, `decide_gate`, `set_slots` в BFF тоже
не реализованы (см. `01-контракты.md`).

## Тема

**Тёмная.** Токены — из эталонного `~/coach/lib/render_html.py` (plan-wN.html):

```
--bg:#0f1115; --panel:#161a22; --panel2:#1d222c; --border:#2a3140;
--text:#e6e9ef; --muted:#9aa3b2;
--accent:#7aa2ff; --accent2:#5cd6c0; --warn:#ff9b6a; --good:#7ee787;
--run:#7ec8e3; --bike:#f08a5a; --swim:#5cd6c0; --ofp:#d8a0ff; --brick:#f0c674;
```

Светлая палитра (`#fdf6ed` и прочие) — из артефактов дизайна и используется
**в документах**, не в приложении. Приложение на телефоне в тёмной теме.

Раскладка карточки тренировки — как в эталоне: иконка вида спорта, название,
тег вида спорта, длительность; ниже — место, время, фокус; ниже — шаги с зоной
справа. Шаги на русском: разминка, работа, отдых, заминка.

Карточка недели: бейдж дня (ВС…СБ), иконка, название, тег, длительность.
Метрики недели — три плитки: часы плана, число сессий, километры.

## Офлайн

**Что доступно без сети:**
- текущая неделя полностью;
- соседние недели — сокращённо (дни и тренировки без шагов);
- сезон — скелетом (фазы, недели, гонки);
- профиль атлета.

**Что требует сети:** новые недели, вытягивание факта, связывание, закрытие недели.
Загрузка факта из Garmin в офлайне невозможна — команда ждёт в очереди.

**Как показывается устаревшее:** в шапке — «данные на <время>», кнопка «обновить».
Кэш хранит `version` состояния; сервер отвечает `304`, если не менялось.

**Размер офлайн-пакета:** ориентир — до 1 МБ на текущую + соседние недели + сезон-скелет.

## Команды в офлайне

Клиент не меняет состояние напрямую — только через команды. Команда, сделанная без сети,
уходит в **outbox** в IndexedDB и уходит на сервер при появлении сети.

```
outbox entry: {id, type, target, args, reason, created_at, attempts, last_error}
```

- `id` генерируется на клиенте — по нему команда идемпотентна при ретраях.
- Порядок сохраняется: команды одного типа зависимы, поэтому outbox — очередь, а не набор.
- Пока команда в outbox, интерфейс показывает «в очереди», а не «сделано».
- Конфликт версии → клиент показывает «состояние изменилось, посмотреть заново?» и
  **не** применяет команду молча.

## Текущая неделя

Номер текущей недели считает **сервер**: клиент спрашивает `GET /api/v1/current-week`
и берёт номер оттуда. В клиенте нет даты начала сезона — при смене горизонта
-season он не устареет молча.

Ручной выбор недели (для отладки и проверки) перекрывает серверный: номер
хранится в `localStorage`.

## Адрес сервера

Приложение ходит на BFF по локальной сети: `http://<ip-машины>:8080`. Адрес
настраивается при первом запуске и запоминается. Внешний доступ отложен — пока
телефон должен быть в домашнем Wi-Fi.

## Авторизация

Авторизации нет — добавим позже (решение Кирилла, 26.10.2026). Клиент не шлёт
`Authorization` и не спрашивает токен.

Место для этого заложено: `api.js` — единственное место, где ходят на сервер,
значит, добавление заголовка там не затронет остальной код.

## События

Клиент подписан на SSE `/api/v1/events`. При сбое — backoff: 1с, 2с, 5с, 15с, 30с.
При обрыве — следующая синхронизация по обычному `GET /snapshot`.

## Кэш в service worker

- Оболочка (HTML, JS, CSS, иконки) — cache-first, обновление в фоне.
- API — network-first; при отсутствии сети — из кэша с отметкой «устарело».
- Никогда не кэшируются: ответы команд и ошибки.

## Работа без сервера вообще

PWA ставится на экран телефона и открывается без сети — показывая кэш. Полноценная работа
невозможна (нет новых данных и нет применения команд), но приложение не выглядит сломанным.
