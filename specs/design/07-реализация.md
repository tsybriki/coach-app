# 07 · Реализация

План работ. Сначала база, чтобы приложение открылось и показало неделю; потом остальное.

## Правила

Стандарт `development-standards`: слои `domain → ports → app → adapters`, зависимости строго
вниз, тест на каждый доменный инвариант, доступ к данным только через порты,
деградация вместо отказа.

Конституция проекта — `.hermes.md` в корне репозитория. Каждое правило — с проверяющей
командой.

## Что не доделано

| Что | Состояние | Почему |
|---|---|---|
| Правило роста формы | заглушка `StubGrowthRule` | вердикт честно отвечает «не могу оценить» |
| Генератор макро-плана | нет | макро приходит импортом из пайплайна: 27 недель из 49, неделя гонки не планируется |
| Переплан остатка недели | команда есть, сборки нет | `replan_remainder` принимается и ничего не строит |
| Команды управления средой | не реализованы | `set_slots`, `override_slots`, `set_equipment`, `set_plan`, `set_goal`, `update_athlete` |
| Команды гейтов | не реализованы | `set_gate_result`, `decide_gate` |
| Ручной факт | не реализована | `edit_actual` — для силовых и ОФП, которых нет в Garmin |
| Экраны клиента | не реализованы | «Цель и достижимость», «Контрольная точка», «Среда» |
| Висяк → слот | не реализована | `place_unplaced`, `unplace_request` |
| Иконки PWA | нет | `manifest.json` объявляет пустой список |
| HTTPS | не решён | без него service worker не регистрируется на телефоне |

## Импорт из пайплайна

`tools/import_pipeline.py` — одноразовая операция: читает `~/coach/state/` и
кладёт в хранилище приложения сезон, профиль, правила методологии, план
недели и факт из Garmin. Импорт ничего не вычисляет — берёт готовые данные.

Запуск:
```bash
.venv/bin/python tools/import_pipeline.py --week 3
```

Номер недели по умолчанию — текущая по дате. `--root` — другой корень данных
(для тестов).

## Этап 1 · Домен

Перенос 21 сущности и 44 инвариантов из `DOMAIN-SPEC.md` в код.

- `app/domain/` — по модулю на агрегат: `entities.py` · `enums.py` ·
  `methodology.py` · `derivations.py`.
- Каждый инвариант — тест. Имена тестов = номера инвариантов (`test_i09_link_is_bidirectional`),
  чтобы связь со спецификацией не терялась. Проверка: `tools/check_invariant_coverage.py`.
- Производные значения — функции, не поля.
- `tests/unit/` — домен без I/O.

**Готово, когда:** 44 теста инвариантов зелёные, `mypy` чистый.

## Этап 2 · Хранилище

- `app/ports/storage.py` — порты хранения: `SeasonRepo`, `FactRepo`, `AthleteRepo`,
  `MethodologyRepo`, `CommandLog`, `DetailRepo`.
- `app/adapters/storage/files.py` — реализация поверх файлов.
- Версия схемы — глобальный счётчик состояния; каталог `migrations/` — когда

- `tools/import_pipeline.py` — импорт из `~/coach/state`, отчёт о расхождениях.
- `tests/contract/test_storage_contract.py` — контрактные тесты портов.

**Готово, когда:** импорт `~/coach/state` даёт рабочее состояние, контрактные тесты
зелёные, `tools/check_storage_leaks.py` не находит утечек.

## Этап 2б · Переход на базу данных

Спланирован заранее, выполняется по триггерам из `02-хранилище.md`.

- `app/adapters/storage/sqlite.py` — вторая реализация тех же портов.
- Схема в SQL — по домену, без JSON-в-колонке.
- `tools/migrate_to_db.py` — перенос данных через порты, со сверкой.
- Переключение — конфигом, оба адаптера живут одновременно.

**Готово, когда:** одни и те же контрактные тесты зелёные для обоих адаптеров,
перенос сверен, а SQLite-адаптер проверен на реальном сезоне.

## Этап 3 · Сервисы

- `app/services/week_planner.py` — вход 2: макро + неделя → тренировки.
- `app/services/week_proposal.py` — сборка недели по правилам методики: макро сезона,
  качественная работа по Дэниэлсу, раскладка по слотам.
- `app/services/week_lifecycle.py` — переходы недели: propose · activate · close ·
  link · unlink · replan.
- `app/services/goal_feasibility.py` — шаг 1: вердикт по достижимости + варианты.
  Правило роста формы берётся из методологии; пока правило — заглушка, вердикт честно
  отвечает «не могу оценить» и не выдумывает число.
- `app/services/assessment.py` — связывание, вердикты, саммари.
- Методология — `app/domain/methodology.py` (язык правил) + `app/adapters/daniels.py`
  (единственный, кто знает формат справочника).

**Готово, когда:** на реальном сезоне 2026–27 планировщик воспроизводит неделю,
не хуже текущего `plan_generate.py`. Сверка макро и планировщика — по всем неделям
сезона (тест `tests/unit/test_macro_planner_agreement.py`).

## Этап 4 · BFF

- `app/api/routes.py` — роуты по `03-BFF.md`, схемы ответов, ETag, SSE, команды.
- `app/api/dependencies.py` — сборка контейнера: адаптеры, порты, сервисы.
- Деградация: Garmin, нарратор. Календаря нет — слоты приходят из состояния.

**Готово, когда:** `curl` отдаёт неделю, команда возвращает diff,

## Этап 5 · Клиент

- PWA по `05-клиент.md`: неделя, детали, разбор, сезон, план против факта, закрытие,
  карточка атлета с окнами тренировок.
- Offline: снапшот в IndexedDB, outbox, service worker.
- SSE-подписка с backoff.

**Готово, когда:** приложение ставится на телефон, открывается без сети и показывает
последнюю неделю; команда в офлайне уходит после появления сети.

## Этап 6 · Хостинг (локальная сеть)

- Бэкап хранилища по расписанию (реализация — в адаптере).

**Готово, когда:** с телефона в домашнем Wi-Fi открывается неделя.

**Внешний доступ отложен** — отдельная задача, варианты разобраны в `04-хостинг.md`.

- Сделано: программа тренировок по фазам (`reference/daniels/training_plan_19_1.json`)

  по этим правилам, а не по каталогу видов тренировок.
- Осталось: перевести каталог видов тренировок (`state/workout_templates.json`)
  в доменные правила.

**Готово, когда:** планировщик собирает неделю из правил методологии, а не из файлов пайплайна.

## Что сознательно не входит в базу

| Не делаем | Почему |
|---|---|
| Регистрация, роли, восстановление пароля | Один пользователь; авторизации нет вовсе |
| Настоящая аутентификация | Отложено. В базе авторизации нет вовсе — заголовка `Authorization` не бывает |
| Push-уведомления | Не запрошены; SSE достаточно |
| Несколько сезонов одновременно | Домен: один активный план |
| Синхронизация между устройствами | Один сервер — один источник правды |
| Импорт/экспорт произвольных форматов | Только свой формат + импорт из пайплайна |
| Логирование в облако | Данные дома |
| Внешний доступ (домен, HTTPS, туннель) | Отложен: в базе только локальная сеть |
| Интеграция с Google Calendar | Доступность — дефолтные слоты в подсистеме «Среда» |
| Загрузка данных Stryd | Берём то, что Stryd складывает в Garmin |

## Порядок и зависимости

```
0 → 1 → 2 → 3 → 4 → 5 → 6
        ↑         ↑
    импорт   план+факт
```

Этапы 1 и 2 независимы от 3–6. Этап 5 (клиент) можно вести параллельно с 3–4: клиент
работает против заглушки API, которая отдаёт снапшот из хранилища.
